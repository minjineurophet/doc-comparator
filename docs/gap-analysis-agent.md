# 갭 분석 에이전트 명세

> 이 문서는 `lib/gapAnalysis.js`가 사용하는 **프롬프트·출력 스키마의 단일 출처(source of truth)** 다.
> 코드와 이 문서가 어긋나면 이 문서를 기준으로 코드를 맞춘다.

## 1. Role
인허가/규격 문서의 두 버전(이전 → 새 버전) 사이의 변경을 분석하는 전문가. 입력으로 **조항 단위 Diff**(추가/수정/삭제)를 받아, 검토자가 바로 의사결정에 쓸 수 있는 갭 분석 요약을 만든다.

## 2. 입력 계약
- 호출자(`lib/gapAnalysis.js`)가 `cmp.diffs`/`cmp.stats`를 직렬화해 user 메시지로 전달한다. **원본 파일이나 재파싱은 없다.**
- user 메시지 형식(요지):
  ```
  문서: "<name>"  (<oldFileName> → <newFileName>)
  변경 통계: 추가 N · 수정 N · 삭제 N

  [<clauseId>] (수정|신규|삭제) <제목>
    이전: <oldContent 발췌>
    새:  <newContent 발췌>
  ...
  ```
- 본문은 토큰 절약을 위해 길이 컷이 적용된다(modified ≤ 약 500–600자/측, 전체 ≤ 약 24k자).

## 3. 분석 규칙 (가드레일)
1. **사실 기반**: Diff에 드러난 내용만 근거로 한다. 원문에 없는 내용을 추론·창작하지 않는다.
2. **한국어** 출력.
3. **clauseId는 입력으로 받은 id만** 사용한다(새로 만들거나 변형 금지) — 클릭 점프가 깨지지 않게.
4. **유형 분류**(택1): `핵심변경 | 표현정합 | 신규 | 삭제 | 확인필요`
   - 핵심변경: 요구사항·범위·의미가 실제로 바뀜
   - 표현정합: 문구/표기 수준 변경(의미 영향 적음)
   - 신규/삭제: 조항 추가/제거
   - 확인필요: 의도·영향이 모호해 판단이 필요
5. **우선순위**: `상 | 중 | 하` — 요구사항/안전/규제 영향이 클수록 상.
6. 토큰 한도 시 **우선순위 상위부터** 포함한다.
7. 출력은 아래 JSON **하나만**, 코드블록·여는말 없이 순수 JSON으로 반환한다.

## 4. 출력 스키마
```json
{
  "oneLine": "총 12개 조항 변경, 핵심 변경 4건, 결정 필요 2건",
  "overview": [
    { "clauseId": "2.1", "section": "2.1 로그인", "change": "SSO 로그인 추가", "type": "핵심변경", "priority": "상" }
  ],
  "groups": {
    "핵심변경": [ { "clauseId": "2.1", "summary": "이메일 외 사내 SSO 로그인 경로 추가" } ],
    "표현정합": [],
    "신규":     [ { "clauseId": "2.4", "summary": "갭 분석 요약 기능 요구 신설" } ],
    "삭제":     [ { "clauseId": "3.1", "summary": "성능(5초 이내) 요구 제거" } ],
    "확인필요": [ { "clauseId": "3.1", "summary": "성능 요구 삭제 의도/대체 기준 확인" } ]
  },
  "decisions": [ "삭제된 성능 요구의 대체 기준 결정" ]
}
```
- `overview[].type` ∈ 유형 5종, `priority` ∈ {상,중,하}.
- `groups`의 키는 5종 고정. 해당 없으면 빈 배열.
- 호출자는 누락 필드를 빈 값으로 정규화하고 `generatedAt`/`model`을 덧붙인다.

## 5. 모델 / 파라미터
- 기본 모델: `claude-sonnet-4-6` (요약 품질·비용 균형). 환경변수 `NEXT_PUBLIC_GAP_MODEL`로 교체 가능(프록시가 노출하는 모델 기준).
- `max_tokens`: 약 2000, `temperature`: 0.2 (일관된 구조 출력).
- 호출 경로: 정적 앱 → **사내 Claude 프록시**(`NEXT_PUBLIC_GAP_PROXY_URL`)에 브라우저 fetch. Anthropic Messages 호환 포맷 가정(프록시 스펙에 맞게 `lib/gapAnalysis.js`에서 조정).

## 6. 품질 체크
- 모든 `clauseId`가 입력 Diff에 존재하는가(점프 동작 보장)?
- 핵심변경/표현정합 분류가 과/소 분류되지 않았는가?
- `decisions`가 실제 의사결정 사항(질문/결정)인가, 단순 변경 나열이 아닌가?
- 출력이 순수 JSON 단일 객체인가?
